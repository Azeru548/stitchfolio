Case study 01 · AI audio

Koe

Hosted text-to-speech for humans and agents: cloud neural quality and offline local inference in one product surface — a free alternative to ElevenLabs. Live studio ↗ · MCP endpoint ↗ · Source ↗

Role Fullstack / AI engineer
Stack Node.js · Express · Docker · SQLite
Domain TTS · developer tooling
graphic_eq

Why more than one engine?

One engine cannot be right for everyone. Microsoft's neural voices sound best and cover 29 languages, but they cost money per character and send the text off the machine. Piper, Kokoro and Kitten run locally: no per-word cost, no network dependency, and different tradeoffs in quality and speed. Koe puts all four behind one interface, so the engine is a per-request choice rather than an architecture decision.

Problem framing

Anyone building an agent, a video pipeline or an accessibility feature needs speech output, but almost every TTS API starts with a corporate account and a card on file. That is a strange gate for a script that takes ten seconds to read.

Koe removes the gate without becoming free infrastructure for the whole internet: anonymous callers get a small allowance, every agent that installs the MCP registers its own key, and a hard instance-wide ceiling means no single caller can burn the box.

Solution shape

An Express server owns one engine registry and one contract — text in, audio bytes out — so edge, Piper, Kokoro and Kitten are interchangeable per request. Work runs through a bounded queue with a 300-second deadline, and quota is charged before synthesis starts, then refunded if the job fails.

Agents connect at POST /mcp over Streamable HTTP with their own free key; humans use the studio at /studio or the plain HTTP API. Audio is ephemeral — signed download links, fifteen-minute TTL — so nothing accumulates on disk.

Architecture

Component responsibilities

Engine registry

Four adapters behind one interface: Microsoft neural voices over the edge CLI, and Piper, Kokoro and Kitten as local processes or sidecars. Health is reported per engine, so an absent sidecar removes one option instead of breaking the product.

Studio and HTTP API

A dependency-free studio at /studio: script, voice, engine, rate and pitch, with job polling and a 600-character preview that streams audio back in seconds, which is the fastest way to judge a voice.

Hosted MCP server

POST /mcp exposes generate_voiceover, list_voices and get_usage to any MCP client, so an agent asks for narration and gets a signed download URL instead of a vendor account.

Quotas, queue and keys

Quota, queue and keys are the load-bearing parts. Free keys are issued behind a proof-of-work gate and stored in SQLite with their counters, so limits survive a restart. The queue runs four workers with twenty slots, a circuit breaker stops hammering an upstream that is already failing, and a kill switch turns generation off before anything is charged.

Decision matrix operators can actually use

Constraint Prefer edge (cloud) Prefer local (Piper / Kokoro / Kitten)
Privacy Text may leave the machine Text must stay on the box
Quality Best naturalness, 29 languages Good to very good, English-first
Speed Seconds, network-bound Kitten fastest, Kokoro close, Piper deliberate
Failure mode Needs connectivity and an upstream Works offline, needs RAM
Output MP3, rate and pitch MP3 (Kokoro) or WAV, rate only

Engineering takeaways

  • · Charge before you synthesise and refund when a job fails, or a free tier becomes someone else's bill.
  • · Bound everything: queue depth, per-job deadline, per-engine word caps. One long script must not stall the box.
  • · Keep engines behind one contract, so an upstream outage costs a voice, not the product.
  • · Make audio ephemeral and hand the caller the file: nothing sensitive accumulates server-side.
